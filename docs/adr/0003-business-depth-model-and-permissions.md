# ADR-0003：业务纵深模型与权限设计

- **状态**：已接受
- **日期**：2026-11-21
- **决策者**：nicknicka

## 背景

现有 CRM 已覆盖客户、联系人、线索、商机与跟进，但 GLOSSARY 定义的完整业务链尚未落地：没有**公海**承接未认领的客户，没有从**报价**到**合同**、**订单**、**回款**的单据流转及**转化**关系。结果是系统只能看到当前对象，无法管理从获客到收款的完整业务过程，也无法回答「钱收回来没有、瓶颈卡在哪里」。

阶段 3 按 GLOSSARY 补齐业务纵深：引入公海与认领机制，新增报价、合同、订单、回款四类单据及其状态流转与转化动作，并把负责人/管理员权限边界延伸到这些新对象。本决策记录其模型形状、关联与权限原则，作为后续实现与评审的依据；具体模型与迁移由各纵向切片 ticket 落地。

## 决策

### 1. 公海用「客户无负责人」表达

不引入独立的公海实体或冗余的归属标记：**公海就是 `ownerId` 为空的客户的集合**。

- 认领：负责人认领公海客户时，把当前用户写入该客户的 `ownerId`，并校验此前 `ownerId` 为空；已被他人认领（已有负责人）时动作失败，避免归属冲突。
- 移入/移出：管理员可清空客户 `ownerId` 使其回到公海，也可指定负责人；负责人不能把客户移入公海。
- 认领成功后复用现有飞书消息卡片能力通知新负责人；通知失败不影响认领业务结果。
- 公海列表即无负责人客户列表，不另存一份数据。

### 2. 单据链：报价 → 合同 → 订单 → 回款

四类单据都关联客户与商机，形成一条可追溯的业务链；每一段转化由显式动作在事务内完成，保证关联正确、不留孤儿数据。

- **报价**：挂在商机下，关联客户与商机；含多个报价条目（名称、数量、单价），金额由条目汇总或显式字段维护。报价可编辑，确认后进入转化链。
- **合同**：由已确认的报价转化而来，关联客户、商机与来源报价；来源可追溯。
- **订单**：由合同转化而来，关联客户、商机与来源合同，进入履约阶段；来源可追溯。
- **回款**：挂在订单下，一笔订单可登记多笔回款，记录金额与到账时间；订单的回款合计为各笔之和，差额为订单金额减去回款合计。

转化关系总结：

| 来源 | 动作 | 目标 | 转化时保留的关联 |
| --- | --- | --- | --- |
| 报价（已确认） | 转为合同 | 合同 | 客户、商机、来源报价 |
| 合同 | 转为订单 | 订单 | 客户、商机、来源合同 |
| 订单 | 登记回款 | 回款 | 订单（并间接关联客户、商机） |

### 3. 负责人/管理员权限边界覆盖全部新对象

新增对象复用现有 CRM 的负责人/管理员边界，不引入第三套角色：

- **负责人**：只能查看与操作自己负责客户关联的报价、合同、订单、回款；对公海客户仅可认领，认领前后均不得访问不属于自己负责客户的单据。
- **管理员**：可访问和操作全部客户与单据，承担财务与业务审计职责；可将客户移入公海或指定负责人。
- **权限落点**：读写收窄在 Server Action / 服务入口内，读取会话与角色后判定，不在页面层做判断；新增对象沿用与现有客户/商机一致的审计字段风格。
- 越权访问或越权转化在服务端被拒绝，不依赖前端隐藏入口。

## 影响

- **正面**：公海不需要独立模型与同步逻辑，归属状态只有一个事实来源（客户的 `ownerId`）；单据链以显式关联保留来源，报价到回款全程可追溯；权限规则一套贯穿新旧对象，降低理解与维护成本。
- **负面**：四类单据相互关联，转化必须在事务内完成并校验关联完整性，否则会出现孤儿数据或越权转化；负责人可见范围依赖客户的 `ownerId`，客户在负责人之间转派或回到公海后，其单据可见范围随之变化，需要由服务端每次按当前归属判定。
- 销售漏斗与客户生命周期由真实业务对象实时派生，不存储手工统计表，也不复制线索/商机原始数据；其实现细节不在本决策范围。
- 本 ADR 只记录模型形状、关联、状态转化与权限原则，不规定字段命名、枚举取值或代码结构；具体以各实现 ticket 为准。

## 替代方案

- **独立公海实体 + 认领记录表**：能让认领历史更显式，但要维护与客户 `ownerId` 的一致性，多一个事实来源；当前阶段只需表达「当前是否有人负责」，故未选。
- **报价/合同/订单/回款只存最后一级关联**（如回款只挂订单、不回溯客户与商机）：模型更简单，但每次查询都要沿链回溯，无法按负责人快速收窄可见范围，也不利于审计，故未选。
- **为新单据单独设计权限表**：灵活但增加一套角色与授权模型，与「沿用负责人/管理员边界、不引入新权限体系」的目标冲突，故未选。
- **用状态字段代替转化动作**（如直接改报价状态为合同）：实现成本低，但无法保留来源关联与事务边界，业务链不可追溯，故未选。
