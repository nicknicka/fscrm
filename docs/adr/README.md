# Architecture Decision Records

本目录记录 fscrm 的重要技术决策。每篇 ADR 对应一个具体决策，说明其背景、选择与影响，便于后来者理解「为什么这样做」，也便于工程技能在改动前核对是否与既有决策冲突。

## 编号与命名

- 文件名格式：`NNNN-<短标题>.md`，其中 `NNNN` 为四位递增序号，从 `0001` 开始。
- 序号在目录内唯一，一旦分配不再回收；新增决策取当前最大序号 + 1。
- 标题使用简短的动宾短语，避免歧义，如 `0001-tech-stack-nextjs.md`。

## 模板

每篇 ADR 使用以下结构：

```markdown
# ADR-NNNN：<决策标题>

- **状态**：提议 / 已接受 / 已废弃 / 被取代
- **日期**：YYYY-MM-DD
- **决策者**：（团队或个人，可留空）

## 背景

为什么需要做这个决策？面对什么问题或约束？

## 决策

我们决定怎么做，以及具体的选择。

## 影响

这个决策带来的正面与负面后果，以及对现有代码、流程的影响。

## 替代方案

考虑过但未选择的方案，以及未选的原因。
```

## 状态流转

- **提议**：已提交但尚未被采纳，或仍在讨论。
- **已接受**：决策被采纳并落实。
- **已废弃**：决策已不再适用，但保留以记录历史。
- **被取代**：被更新的决策（ADR-NNNN）替代，正文中注明取代它的新 ADR。

状态变更时，直接更新本篇的状态字段，并在「影响」中补一句说明变更原因。
