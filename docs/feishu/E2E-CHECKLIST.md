这是一份给**人工操作员**使用的「真机端到端」复核清单。这里的“真机”特指：使用真实飞书账号、真实飞书租户、真实 OAuth 授权、真实飞书消息与真实 Postgres 数据库，由人按顺序执行并观察结果。

## 凭证与 Secret 规则

- 所有命令都从本地环境变量读取配置；真实值只放在 gitignore 的 `.env.local`（或部署环境的密钥管理）中。
- 本文件和记录中只写变量名、错误码、时间、环境与结果，不写 `FEISHU_APP_SECRET`、`SESSION_SECRET`、数据库密码、访问令牌、Cookie 或任何真实 Secret。
- 不要 `cat .env.local`，不要把环境变量整段打印到终端或日志；确认配置是否存在即可，例如只检查非空，不输出值。
- 本工单没有调用真实飞书 API，没有读取或轮换任何凭证，也没有修改 `.env.local`。任何“通过”结论都必须来自人工操作员亲自定义的执行。

- [ ] 真实飞书账号已在 CRM `users` 表绑定 `feishuOpenId`，且角色/负责人范围正确；若尚未绑定，先由人工操作员按流程完成，不要为了测试写假绑定。

## 建议执行顺序

1. **OAuth 登录**：取得真实会话。
2. **通讯录同步**：确认真实飞书用户落到数据库，后续事件匹配才有依据。
3. **消息卡片**：创建带真实负责人的客户或商机，并检查负责人是否收到卡片。
4. **长连接事件**：单独启动 `npm run feishu:events`，给机器人发消息，核对日志里的 CRM 负责人匹配。

登录未通过时，不要执行后续依赖 CRM 会话的链路；把它标为“受阻”，写明错误码与修复动作，并在修复后重跑。

## 真机验证清单

### 流程 A：飞书 OAuth 登录进入 CRM

**执行人**：人工操作员　**前置**：后台重定向 URL 与 user scope 已发布，测试账号已绑定 CRM 负责人

- [ ] **A1 发起登录**
  - 命令/动作：运行 `npm run dev`，浏览器打开 `http://localhost:3000/login`，点击「使用飞书登录」。
  - 预期结果：跳转到飞书授权页；若未登录飞书，先出现飞书登录页；授权页显示的权限与 `FEISHU_OAUTH_SCOPE` 一致。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 A」。
- [ ] **A2 完成授权并进入 CRM**
  - 命令/动作：使用真实飞书账号同意授权。
  - 预期结果：回调到 `/api/auth/feishu/callback`，再跳转回 CRM 受保护页面（默认 `/`）；页面可用，能看到当前登录用户对应的负责人范围。
  - 失败观察：登录页 `error=` 参数可能出现 `cancelled`、`denied`、`invalid_state`、`config_missing`、`unbound`、`auth_failed`；逐字记录，不要猜测。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 A」。

### 流程 B：客户/商机创建 → 飞书消息卡片收到

**执行人**：人工操作员　**前置**：流程 A 已取得会话；测试用户已绑定 `feishuOpenId`；机器人能力与 tenant 权限已发布

- [ ] **B1 创建客户并确认卡片**
  - 命令/动作：在 CRM 进入「客户」页，点「新建客户」，填写可识别的测试名称（例如包含日期），在「负责人」中选择已绑定飞书的真实账号，提交。
  - 预期结果：客户写入成功；该负责人在飞书中收到 `customer_created` 消息卡片；CRM 页面能看到刚创建的客户。
  - 注意：通知失败不会影响业务写入；页面成功不代表卡片已收到，必须检查飞书客户端。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 B1」。
- [ ] **B2 创建商机并确认卡片**
  - 命令/动作：进入「商机」页，点「新建商机」，填写测试名称，关联刚创建的客户，选择同一位已绑定飞书的负责人，提交。
  - 预期结果：商机写入成功；该负责人在飞书中收到 `opportunity_created` 消息卡片；CRM 页面能看到刚创建的商机。
  - 失败观察：若业务写入成功但收不到卡片，查看应用服务端日志的 `[feishu:notify]` 行（可能包含飞书返回码），以及飞书后台权限/机器人能力是否已发布。不要把日志中的令牌或 Cookie 复制到记录里。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 B2」。

### 流程 C：长连接事件——给机器人发消息 → 服务端日志显示事件 + CRM 负责人匹配

**执行人**：人工操作员　**前置**：流程 D 已确认真实飞书用户落库；后台已订阅 `im.message.receive_v1` 且长连接订阅方式已保存

- [ ] **C1 启动长连接**
  - 命令/动作：在独立终端运行 `npm run feishu:events`，保持运行。
  - 预期结果：终端出现 SDK 长连接在线日志（既往记录中的形式为 `[ws] ws client ready`），进程未退出。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 C」。
- [ ] **C2 发送消息并检查事件日志**
  - 命令/动作：用已绑定 CRM 负责人的真实飞书账号给机器人发送一条测试消息（单聊；若用群聊则按后台订阅规则 @机器人）。
  - 预期结果：终端打印 `[feishu:event] 收到消息 messageId=... chatId=... type=... from=CRM用户:<姓名>`，`from` 必须匹配预期 CRM 负责人，而不是只显示 open_id 或“未知”。
  - 失败观察：若日志只有 open_id / 未知用户，说明该飞书账号未绑定到 CRM 用户或 `open_id` 不一致；若完全没有事件，核对后台事件订阅、发布版本与长连接是否在线。
  - 收尾：按 `Ctrl+C` 停止长连接。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 C」。

### 流程 D：通讯录同步 → 用户落库

**执行人**：人工操作员　**前置**：tenant 通讯录权限已发布；数据库可写

- [ ] **D1 执行同步**
  - 命令/动作：运行 `npm run feishu:sync-contacts`（或在 CRM 设置页点「立即同步通讯录」），然后用只含待确认字段的只读查询检查 Postgres `users` 表（例如查询姓名与 `feishuOpenId` 是否非空；不要查询或复制数据库密码等 Secret）。
  - 预期结果：脚本正常结束；真实飞书用户出现在 Postgres `users` 表且 `feishuOpenId` 正确写入；重复运行不产生重复用户。
  - 失败观察：飞书返回码如 `99991672`（权限未开通/未发布）要原样记录；部门数为 0 但用户已落库，按已配置可见范围记录，不要写成“全部通过”。
  - 记录：时间 / 环境 / 结果 / 错误码 → 见下方「记录模板 D」。

## 结果判定

- **未通过**：动作执行了，但预期结果未出现；必须填写错误码或日志线索与下一步修复动作。
- **受阻**：因后台权限、重定向 URL、发布版本、账号绑定或数据库配置未就绪而无法执行；必须写明缺失项，修复后重跑。
