## 本文件的用途与边界

这是一份给**人工操作员（运维）**按顺序执行的 App Secret 轮换清单，以及一份交接/状态记录模板。轮换动作发生在飞书开放平台后台和本地环境变量中，本工单**只产出清单与交接记录，不替用户执行后台轮换**。

本文件的编写会话**没有生成新 Secret、没有修改 `.env.local`、没有重启进程、没有调用真实飞书 API、没有读取或轮换任何凭证**；下方所有记录初始状态均为 **待执行 / 待确认**，不存在任何已完成的轮换或复验结论。任何“通过 / 已轮换”必须由实际执行的人按真实证据填写。

## 凭证与 Secret 规则（必须遵守）

- 真实凭证（飞书应用凭证的 `App Secret`、`SESSION_SECRET`、数据库密码、访问令牌、Cookie）**只写入本地环境变量**：gitignored 的 `.env.local`（或部署环境的密钥管理服务）。不得提交到仓库，不得写入日志、测试快照或交接记录。
- 本文件和记录中只写变量名、错误码、时间、环境与结果，不写任何真实 Secret 的值；`.env.example` 仅保留空占位符，不得填入真实值。
- 不要 `cat .env.local`，不要把环境变量整段打印到终端或日志；确认配置是否存在只检查是否非空，不输出值。
- 本文件不提供任何读取或打印真实凭证的命令，所有步骤由人工在后台和本地环境中完成。

## 旧凭证作废时机（重要）

按照飞书开放平台的生成流程，在后台**生成新 Secret 的同时或确认生成后，旧 Secret 即进入作废流程**（可能立即失效，或在新 Secret 生效后很短的时间内失效；具体以飞书开放平台后台提示为准）。因此：

1. 生成新 Secret 后，必须**立即**完成下方步骤 2（更新本地环境变量）与步骤 3（重启相关进程），不要长时间停留在“后台已生成、本地未更新”的中间状态。
2. 飞书开放平台后台若提供“旧 Secret 保留期 / 停用旧 Secret”的选项，应在新 Secret 通过四项真机复验前**保持旧 Secret 可用（不主动撤销）**，以便验证失败时回滚。
3. **只有在步骤 4 的四项真机验证全部通过、步骤 5 记录完成后**，才可回到后台执行步骤 6：主动撤销/作废旧 Secret。在此之前，不要手动废止旧 Secret。
4. 如果后台在生成新 Secret 时已自动立即使旧 Secret 失效，则“保留旧 Secret 用于回滚”的前提不存在；此时若验证失败，按回滚步骤恢复为仍可用的旧值，或重新生成一对新旧凭证并重试。

## 有序轮换清单（人工执行）

执行人：人工操作员（运维）。每一步完成后按下方模板更新状态、时间戳和结果；失败项不要填写“通过”。

### 步骤 1：在飞书开放平台后台生成新 Secret

- 动作：由有后台权限的操作员登录[飞书开放平台](https://open.feishu.cn)，进入对应自建应用的「凭证与基础信息」，生成新的 App Secret。
- 记录：只记录操作人、时间、后台环境（飞书 / Lark、应用）与生成动作是否成功；**不要复制或记录新 Secret 的值到仓库、工单、日志或聊天记录**。
- 状态：待执行 / 待确认。

### 步骤 2：更新本地环境变量

- 动作：在本地（或部署环境的密钥管理服务）更新 `FEISHU_APP_SECRET` 为新值。本地开发环境通过 gitignored 的 `.env.local` 注入；`.env.example` 的占位符保持不变。
- 注意：只确认变量非空即可，不要输出值；`FEISHU_APP_ID`、`FEISHU_OAUTH_REDIRECT_URI` 等非 Secret 配置不应在此步骤顺手改动，避免引入额外变量。
- 状态：待执行 / 待确认。

### 步骤 3：重启相关进程

- 动作：重启所有读取该环境变量、且缓存了飞书客户端或访问令牌的进程。至少包括：
  - 本地开发服务器（`npm run dev`）；
  - 事件长连接进程（`npm run feishu:events`）；
  - 通讯录同步脚本进程（`npm run feishu:sync-contacts`）及任何常驻的同步任务；
  - 部署环境中的对应服务/worker（按部署流程重启，确保新 Secret 注入生效）。
- 原因：飞书客户端为进程内单例并缓存令牌（见 `README.md`）；不重启可能仍使用旧凭证或旧令牌，导致“已更新但验证失败”的假象。
- 状态：待执行 / 待确认。

### 步骤 4：重跑阶段 1 的四项真机验证

- 动作：按 [`docs/feishu/E2E-CHECKLIST.md`](./E2E-CHECKLIST.md) 的真机清单，用真实飞书账号、真实租户/数据库重新执行四条链路；每条链路的结果以该清单的记录模板为准：
  1. 飞书 OAuth 登录进入 CRM（清单流程 A，记录模板 A）；
  2. 客户/商机创建 → 飞书消息卡片（清单流程 B，记录模板 B1 / B2）；
  3. 长连接事件与 CRM 负责人匹配（清单流程 C，记录模板 C）；
  4. 通讯录同步用户落库（清单流程 D，记录模板 D）。
- 判定：使用清单中的“通过 / 未通过 / 受阻 / 待执行 / 待确认”。`npm test` 通过不等于真机复验通过；自动化测试和既往验证记录 [`docs/feishu/VERIFICATION.md`](./VERIFICATION.md) 中的结果都不作为本次通过依据。
- 顺序：登录未通过时不要执行依赖 CRM 会话的后续链路，将其标为“受阻”并记录错误码。
- 状态：待执行 / 待确认。

### 步骤 5：记录结果

- 动作：把步骤 1—4 的执行人、时间（含时区）、环境、结果、错误码与证据位置填入下方模板；四条真机链路的复验结果引用/回填 [`docs/feishu/E2E-CHECKLIST.md`](./E2E-CHECKLIST.md) 的对应记录模板。
- 注意：证据位置只写路径或截图名，不含 Secret 或令牌值。状态为“未通过 / 受阻”时写明修复动作，不要写成“通过”。
- 状态：待执行 / 待确认。

### 步骤 6：验证全部通过后才撤销旧 Secret

- 前置：步骤 4 四项真机验证**全部通过**，步骤 5 已记录，且本文件状态更新为“已通过”。
- 动作：回到飞书开放平台后台，按后台提示撤销/作废旧 Secret（或结束其保留期）。记录执行人、时间与结果；**不要记录任何 Secret 值**。
- 若任一验证未通过或受阻：不要执行本步骤，直接进入下方回滚步骤。
- 状态：待执行 / 待确认。

## 验证失败回滚步骤

在步骤 6 之前（旧 Secret 仍可用时）：

1. 停止正在使用新 Secret 的相关进程（开发服务器、长连接、同步脚本）。
2. 将本地环境变量 `FEISHU_APP_SECRET` 恢复为仍可用的旧值（只改 gitignored 的 `.env.local` 或部署密钥管理中的变量；不要修改 `.env.example`）。
3. 重启步骤 3 列出的相关进程，确保进程内单例与令牌缓存重新加载。
4. 重新按 [`docs/feishu/E2E-CHECKLIST.md`](./E2E-CHECKLIST.md) 运行四项真机验证；逐项确认恢复通过，并把回滚动作、时间与结果填入下方“回滚记录”。
5. 在后台确认旧 Secret 未被撤销；若后台已自动作废旧 Secret，则无法回滚到旧值，需重新生成凭证并从头执行本清单。

在步骤 6 之后（旧 Secret 已撤销）：旧的 Secret 值已不可用，不能“恢复旧 Secret”。只能重新生成一对新凭证，按步骤 2—5 更新并复验；把旧值标记为已撤销，不要复用。回滚是否成功以四项真机验证复测结果为准，不以“配置已改回”为准。
